## Deskripsi

The self-hosted n8n automation instance at `https://n8n.srv651498.hstgr.cloud` runs **n8n 2.8.3**, which is within the affected range (< 2.9.3 / 2.10.1 / 1.123.22) of CVE-2026-27578 (GHSA-2p9h-rqjw-gm92): an authenticated user with permission to create or modify workflows can inject arbitrary scripts into pages rendered by n8n (Form Trigger, Chat Trigger, Send & Wait, Webhook, and Chat nodes), executing in other users' browsers and enabling session hijacking and account takeover. The same instance also falls in the affected ranges of CVE-2026-27496 (Task Runner in-process uninitialized-memory disclosure, fixed in the same versions, requires `N8N_RUNNERS_ENABLED=true`). Version confirmed from the instance's own `/rest/settings` and page metadata during this scan.

## Dampak

This n8n instance handles the platform's payment workflows (`/webhook/midtrans-aistaff`, Midtrans integration) and is reachable on the public internet. If any workflow editor account is compromised (or obtained via a future auth weakness), stored XSS via these nodes would let an attacker hijack sessions of other n8n users — potentially the payment workflow owner — and read or modify payment-handling workflows, credentials, and integrations. Task-runner memory disclosure (CVE-2026-27496) could leak in-process secrets on the same host if runners are enabled.

## Bukti

**Advisory evidence:** `CVE-2026-27578` applies to `n8n` at installed version `2.8.3`.

**Usage analysis:** imported by application code; affected API usage unconfirmed. The vulnerable component IS deployed and internet-reachable: `GET https://n8n.srv651498.hstgr.cloud/rest/settings` → 200 with n8n instance metadata confirming deployment of the platform itself (`settingsMode: public`, authenticationMethod: email); page HTML at `/` embeds n8n runtime configuration. The vulnerable node surface (Form Trigger, Chat Trigger, Webhook, Chat nodes) cannot be confirmed without an editor credential — `/rest/workflows`, `/rest/credentials`, `/rest/executions` all return 401 unauthenticated, and `/rest/owner/setup` returns 404 (instance already claimed), so no unauthenticated entry into the editor was found. Precondition source→sink trace: public webhook endpoints (`/webhook/*`, e.g. `/webhook/midtrans-aistaff`) are unauthenticated entry points, but the advisory's XSS sink requires the attacker to first create/modify a workflow as an authenticated editor — that hop is blocked today by enforced email auth (verified via 401s on all `/rest/*` editor routes). This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Rekomendasi Perbaikan

Upgrade the self-hosted n8n instance to a version at or above **2.10.1** (or 2.9.3+) to remediate CVE-2026-27578 and CVE-2026-27496. As an interim mitigation: restrict workflow creation/editing permissions to fully trusted users only, and disable the Webhook node via `NODES_EXCLUDE` if not needed. Confirm `N8N_RUNNERS_ENABLED` is not set to `true`; if runners are required, use `N8N_RUNNERS_MODE=external`.
